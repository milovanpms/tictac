Detailed Description

Fichier d'en-tête pour la gestion de l'écran e-paper 1.54" Waveshare.

Author
Milovan PMS

Ce fichier contient les déclarations des fonctions et structures nécessaires pour contrôler l'écran e-paper 1.54" via l'interface SPI. L'écran utilise un mode d'affichage noir et blanc avec support du mode partiel pour des mises à jour plus rapides.

Note
Basé sur la documentation Waveshare : https://www.waveshare.com/wiki/1.54inch_e-Paper_Module_(B)_Manual#Working_With_STM32

void EPD_Init ( void )

Initialise l'écran e-paper en mode complet.

Effectue l'initialisation complète de l'écran e-paper, alloue la mémoire pour le buffer d'image et configure la bibliothèque graphique Paint. Ce mode permet un contrôle total de l'écran mais les mises à jour sont lentes.

Precondition
L'interface SPI doit être initialisée
Le module DEV doit être initialisé
Postcondition
L'écran est prêt pour l'affichage en mode complet
Le buffer d'image est alloué et initialisé
Note
Utilise malloc() pour allouer le buffer d'image

Cette fonction effectue l'initialisation complète de l'écran e-paper en mode standard. Elle configure l'écran, efface son contenu, alloue la mémoire nécessaire pour le buffer d'image et initialise la bibliothèque graphique.

Le mode complet permet un contrôle total de l'écran mais les mises à jour sont relativement lentes (plusieurs secondes).

Precondition
L'interface SPI doit être initialisée via EPD_SPI_Init()
Le module DEV doit être configuré
Postcondition
L'écran est initialisé et effacé
Le buffer d'image est alloué et configuré avec fond blanc
La bibliothèque Paint est initialisée avec rotation de 90°
Note
La mémoire est allouée dynamiquement avec malloc()
En cas d'échec d'allocation mémoire, la fonction retourne sans initialiser

◆ EPD_Init_Partial()

void EPD_Init_Partial ( void )

Initialise l'écran e-paper en mode partiel.

Initialise l'écran d'abord en mode complet avec un fond noir, puis passe en mode partiel pour permettre des mises à jour plus rapides de zones spécifiques de l'écran. Idéal pour les applications temps réel.

Precondition
L'interface SPI doit être initialisée
Le module DEV doit être initialisé
Postcondition
L'écran est configuré en mode partiel avec fond noir
Le buffer d'image est alloué et initialisé
Note
Le mode partiel permet des mises à jour plus rapides mais avec certaines limitations

Initialise l'écran e-paper en mode partiel.

Cette fonction initialise l'écran e-paper en mode partiel, qui permet des mises à jour beaucoup plus rapides que le mode complet. Le processus se fait en deux étapes :

  1. Initialisation complète avec fond noir
  2. Passage en mode partiel pour les mises à jour suivantes

Le mode partiel est idéal pour les applications temps réel comme l'affichage de l'heure, du nombre de pas, etc.

Precondition
L'interface SPI doit être initialisée via EPD_SPI_Init()
Le module DEV doit être configuré
Postcondition
L'écran est initialisé en mode partiel avec fond noir
Le buffer d'image est alloué et configuré avec fond noir
La bibliothèque Paint est initialisée avec rotation de 90°
Note
Le délai de 200ms permet à l'écran de terminer le rafraîchissement initial
Le buffer est initialisé avec 0x00 (noir) au lieu de 0xFF (blanc)
En cas d'échec d'allocation mémoire, la fonction retourne sans initialiser

◆ EPD_SPI_Init()

void EPD_SPI_Init ( void )

Initialise l'interface SPI pour l'écran e-paper.

Configure les broches GPIO (PA5=SCK, PA6=MISO, PA7=MOSI) et initialise le périphérique SPI1 avec les paramètres optimaux pour l'écran e-paper.

Precondition
Les horloges GPIOA et SPI1 doivent être disponibles
Postcondition
L'interface SPI est configurée et prête à communiquer avec l'écran
Note
En cas d'erreur d'initialisation, le programme entre dans une boucle infinie

Initialise l'interface SPI pour l'écran e-paper.

Cette fonction configure les broches GPIO nécessaires pour la communication SPI (SCK, MISO, MOSI) et initialise le périphérique SPI1 avec les paramètres optimaux pour l'écran e-paper 1.54".

Configuration SPI :

  • Mode maître
  • Prescaler de 8 pour ajuster la vitesse
Precondition
Les horloges des périphériques GPIOA et SPI1 doivent être disponibles
Postcondition
L'interface SPI est configurée et les interruptions sont activées
Les broches PA5 (SCK), PA6 (MISO), PA7 (MOSI) sont configurées
Note
En cas d'échec de l'initialisation, le programme entre dans une boucle infinie
La priorité d'interruption SPI est configurée à 3 (priorité basse)
